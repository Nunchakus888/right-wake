## Breaking namespace reset

This release uses the current names directly. It does not provide previous-name aliases, fallback binary/profile discovery, historical image-source acceptance, or automatic migration of old configuration, state, or approval artifacts. Install the current CLI and plugin, use a fresh profile, and configure the desired sources and existing-thread bindings under the new names.

Existing event-driven execution and trust boundaries remain: no idle model polling, no automatic replacement work thread, durable scoped ownership and queues, and independently approved external replies. An incoming payload cannot change the execution host, thread, working directory, credentials, or approval policy.

## Distribution

Native packages cover macOS/Linux arm64/x86_64. Linux amd64/arm64 Docker-load packages use the corresponding tested native binaries. The release workflow publishes:

- `right-wake-v0.2.0-TARGET.tar.gz` for each native target.
- `right-wake-v0.2.0-container-linux-amd64.tar.gz` and `right-wake-v0.2.0-container-linux-arm64.tar.gz`.
- `SHA256SUMS`, `install.sh`, `install-container.sh`, and `compose.yaml`.

SQLite remains embedded; no database service is needed. The native binary keeps the existing SQLite runtime floor of 3.51.3 and database schema version 3. These retained internal versions do not imply migration support for a previous namespace.

Use [installation](https://github.com/Nunchakus888/right-wake/blob/main/docs/installation.md), [the Codex plugin](https://github.com/Nunchakus888/right-wake/blob/main/docs/plugin.md), [Linear setup](https://github.com/Nunchakus888/right-wake/blob/main/docs/linear.md), or [Docker deployment](https://github.com/Nunchakus888/right-wake/blob/main/deploy/README.md). Real provider registration, public WSS operation, real original-thread model continuation, and desktop concurrency remain separate items in [acceptance](https://github.com/Nunchakus888/right-wake/blob/main/docs/acceptance.md).
