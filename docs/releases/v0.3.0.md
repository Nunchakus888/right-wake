# RightWake v0.3.0

**Wake the right Agent thread.**

This experimental release addresses two concrete onboarding gaps: watching new comments on issues assigned to a Linear user plus newly assigned tasks, and delivering work through a supported Codex queue without requiring the direct adapter's exclusive-writer condition.

## What changes

### Personal Linear watching

A Linear source can set `linear_assignee_id` with an explicit organization. New comments need no mention; genuine assignment transitions and newly created assigned issues can wake work. Issue snapshots maintain the observed owner across task transfers, removals, duplicate/late deliveries, and equal-version conflicts. Unknown ownership waits without invoking a router or model. Held eligible events respect pending-work capacity.

`source linear-import` imports a strict, partial issue/assignee/revision baseline; `source linear-state` reports the durable projection and waiting counts. A saved issue list is not a permanent allowlist, subscription registration, or destination binding. Existing bindings route first; unbound work still requires permitted context evidence and an existing-thread claim. No replacement thread is created.

The worker acts on its latest verified ownership evidence. It cannot infer undelivered changes; refresh known gaps, including previously tracked issues now assigned elsewhere. Both relay and local worker need the personal source policy and baseline. See the [Linear guide](https://github.com/Nunchakus888/right-wake/blob/main/docs/linear.md).

### Optional Codex queue delivery

`host add --delivery queue` explicitly selects the experimental App Server queue. It must connect to the original thread's owning shared server; another server reading the same history does not coordinate Desktop writes. The default remains direct `tool-output`, with its exclusive-writer requirement.

Queue submission contains a fixed notice and dispatch UUID. The original thread retrieves immutable event/context data through the new `right_wake_dispatch_context` MCP tool on the worker's profile. A successful retrieval is required before accepting a completed router result or draft. The adapter correlates the unchanged message, client ID, thread, and turn; ambiguous post-submission results remain unknown, with no blind retry. It never forces a paused queue to start.

Both delivery modes need a real restricted tool/credential boundary. Queue changes admission, not the existing thread's remote tool permissions. `host inspect --host HOST --thread UUID` verifies protocol and target identity without submitting a model turn; it cannot prove Desktop ownership, tool availability, or that a missing queue entry was never delivered. See [host compatibility](https://github.com/Nunchakus888/right-wake/blob/main/docs/host-compatibility.md).

### Installation and diagnostics

The setup Skill now distinguishes desired scope, saved baseline, signed receipt, and original-thread execution. It reuses prior state and prepares an exact, secret-free administrator handoff when webhook administration or an endpoint is missing. The plugin retains three skills and now exposes twelve MCP tools. `doctor` summarizes personal assignment state without dumping the issue inventory.

## Upgrade

Refresh an already-registered marketplace using the local Codex CLI:

```sh
codex plugin marketplace upgrade right-wake --json
codex plugin add right-wake@right-wake --json
codex plugin list --marketplace right-wake --json
```

Run the updated `$right-wake-setup` in the intended local environment. It should stop an owned running receiver when necessary, preserve a backup, install the pinned 0.3.0 native release, and reuse the same profile, sources, bindings, secrets, and onboarding record. Personal filtering requires the new binary as well as the skill.

Database schema **4** adds ownership and dispatch-context tables to current-name 0.2.0 profiles. Existing hosts retain direct delivery until explicitly changed. Roll back with the matching pre-upgrade state backup; do not run the older binary against the upgraded database. Bundled SQLite remains **3.54.1**. The 261 registry dependencies and their checksums are unchanged.

Native packages cover macOS and glibc Linux on x86_64/arm64. Linux Docker-load images support a persistent VPS relay. Installation, checksums, exact CI runs, and public-download checks are recorded in [v0.3.0 verification](https://github.com/Nunchakus888/right-wake/blob/main/docs/releases/v0.3.0-verification.md).

## Remaining deployment prerequisites

Linear MCP read access does not grant webhook administration or create a public receiver. A workspace administrator or an authorized admin client must register the intended Issue/Comment coverage to the actual HTTPS endpoint. Private teams require their intended explicit coverage. Original-thread execution also needs a verified supported host, identity, context tool, and tool restrictions.

Protocol fixtures and an isolated official Codex 0.166.0 probe validate method availability and rejection behavior without authentication or model work. They do not establish a real YCloud subscription, a specific user's baseline import, or live Desktop continuation. Those outcomes remain explicit in the [acceptance ledger](https://github.com/Nunchakus888/right-wake/blob/main/docs/acceptance.md).
