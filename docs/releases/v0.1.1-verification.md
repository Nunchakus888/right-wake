## Actual SQLite engine and v0.1.0 data compatibility

The new binary reports Waking `0.1.1` and actually links **SQLite 3.54.1**, through `rusqlite 0.41.1` / `libsqlite3-sys 0.39.1`. Its SQL `sqlite_source_id()` is:

```text
2026-10-16 14:45:20 555e07ef33f69a0957d24d8e555b702464a131d6f1607f4c3c1e4551e8e6ca76
```

The runtime version/source ID matches the [upstream 3.54.1 release](https://sqlite.org/releaselog/3_54_1.html). SQLite's [WAL documentation](https://www.sqlite.org/wal.html#the_wal_reset_bug) identifies the WAL-reset fix in mainline 3.51.3 and later. Waking now checks the linked engine before opening state and refuses versions below that mainline floor; `doctor` exposes the actual version. The host's separate `sqlite3` executable does not determine this result.

For upgrade compatibility, the public v0.1.0 Linux x86_64 release archive and extracted executable were verified against their published checksums. That original executable created a fresh isolated demo profile with two events and two drafts. The new v0.1.1 binary then opened the old profile, listed its drafts, created a database backup, and opened a separate restore of that backup.

**All rows in all 13 tables remained identical**, including every field of both drafts. Database schema version remained **3**; the backup had mode **0600**, and `integrity_check` returned `ok`. This is real old-version state compatibility evidence, not a claim that the rare upstream WAL-reset race was reproduced. The synthetic demo made zero provider calls, external replies, or idle model calls.

## Integration limits

Live Linear webhook registration, public HTTPS/WSS deployment, offline local replay against that public deployment, and real model continuation on the user's exact existing host/thread still need deployment-specific acceptance. Provider writes require separate authorization and verification. This release does not add an OpenAI-hosted Codex Cloud adapter or migrate local Codex history into a container. See the [acceptance ledger](../acceptance.md) and [host compatibility](../host-compatibility.md).
