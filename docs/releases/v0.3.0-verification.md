### Same-profile upgrade and rollback exercise

An isolated profile created by the actual publicly installed **0.2.0** binary contained two completed mock jobs, two drafts, two bindings, and an unused Codex host configuration. Its private SQLite backup had schema **3**. Opening the same profile with the new binary upgraded it to schema **4** while preserving every row of deliveries, events, resources, bindings, cards, jobs, drafts, and audit, and preserving the configuration bytes. The old Codex host resolved to default `tool_output`; no implicit Queue opt-in occurred.

Restoring the pre-upgrade database and configuration to a separate profile allowed the original 0.2.0 binary to open it successfully with the original state. This exercised an actual current-name upgrade and backup-based rollback, without a real host, model, service manager, or provider call.
